# RAG 技术演进：从"做空"到参数化注入

## 背景

2025 QCon 上海站，清华大学艾清遥博士发表了《让外部知识"长入"模型：动态化与参数化 RAG 技术探索》演讲，整理自 InfoQ。

## 核心观点

### 传统 RAG 的三大痛点

1. **何时检索**：人为规定，非模型自主判断（每问必搜 or 人工预设节点）
2. **检索什么**：查询构造依赖人工模板，无法深入模型内部真实需求
3. **如何注入**：把文档塞进提示词 → 上下文膨胀、lost in the middle

### 动态检索 DRAGIN

用轻量级 **monitor 模块**实时监测模型内部状态：
- 监测 token 生成时的**概率分布熵值**（熵值升高 = 信息缺口）
- 监测**注意力网络激活模式**（找出下一个待生成 token 关联最紧密的关键 token）
- 仅在模型真正需要时触发检索，检索调用量显著下降

### 参数化 RAG（Parametric RAG）

颠覆"塞进提示词"的做法：

1. 为每篇文档训练一个**轻量级 LoRA 适配器**（离线，单篇文档约 12x token 数量代价）
2. 线上推理时，**直接注入 LoRA 权重到模型前馈网络**，不再传递文档 token
3. 多文档场景：LoRA 权重直接相加，一次性更新模型参数
4. **优势**：消除在线 token 消耗，推理速度提升约 30%；文档越长优势越明显

### 两种 RAG 的适用场景

| 范式 | 擅长 | 不擅长 |
|------|------|--------|
| In-context 注入 | 简单事实型问答 | 长文档、推理、多文档聚合 |
| Parametric RAG | 需要整合分散信息、推理 | 精确 token 匹配 |

**最优解**：两者混合使用。

## 行业趋势

- **上下文窗口扩大**正在"杀死"RAG（模型直接吞得下整本书）
- 但纯延长上下文不能解决所有问题（lost in the middle、计算成本）
- **动态检索 + 参数化注入**是 RAG 进化的下一跳
