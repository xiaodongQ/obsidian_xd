# LLM Wiki 模式

## 1. 概述

LLM Wiki 是一种利用 LLM 构建个人知识库的模式。其核心思想是：LLM 不是在查询时从原始文档中重新发现知识，而是**增量构建和维护一个持久的 Wiki**——一个位于原始资料和用户之间的结构化、互相链接的 Markdown 文件集合。

## 2. 核心理念

**传统 RAG 的问题**：每次提问都要重新检索相关片段，综合五个文档的细微问题需要反复查找和拼凑。没有积累。

**LLM Wiki 的解决**：Wiki 是持久积累的工件。交叉引用已经存在，矛盾已被标记，综合内容反映了你读过的所有材料。每添加一个源，Wiki 就变得更丰富。

## 3. 关键特性

1. **持久性** - Wiki 是一个持久的、不断累积的产物，而非每次查询时重新生成
2. **增量维护** - 新源文档不是简单索引，而是被读取、提取、整合进现有 Wiki
3. **AI 编写** - 用户负责 sourcing、探索和提问，LLM 负责所有繁琐工作（总结、交叉引用、归档、记录）
4. **双向协作** - LLM 在一侧编辑，用户在 Obsidian 中浏览结果

## 4. 应用场景

- **个人**：追踪目标、健康、心理、自我提升——归档日记、文章、播客笔记
- **研究**：深入研究某个主题数周或数月——阅读论文、文章、报告，逐步构建综合 Wiki
- **阅读书籍**：将每章归档，构建人物、主题、情节线索的页面
- **团队**：Slack 线程、会议记录、项目文档、客户通话维护的内部 Wiki
- **其他**：竞品分析、尽职调查、行程规划、课程笔记、爱好深入研究

## 5. 架构

### 5.1. 三层架构

| 层级                    | 说明                                                                 |
| --------------------- | ------------------------------------------------------------------ |
| **Raw Sources（原始资料）** | 精选的源文档集合（文章、论文、图片、数据文件）。不可变，LLM 只读不修改。这是真相来源。                      |
| **Wiki（维基）**          | LLM 生成的 Markdown 文件目录（摘要、实体页面、概念页面、比较、概述、综合）。LLM 全权负责此层。           |
| **Schema（模式）**        | 告诉 LLM Wiki 结构、约定和workflow的文档（如 Claude Code 的 CLAUDE.md）。这是关键配置文件。 |

### 5.2. 操作流程

**Ingest（摄入）**：将新源放入原始集合，告诉 LLM 处理。典型流程：
1. LLM 读取源文档
2. 与用户讨论关键收获
3. 写入相应的 Wiki Markdown 文件
