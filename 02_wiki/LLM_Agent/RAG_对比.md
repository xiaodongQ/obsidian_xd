# RAG 与 LLM Wiki 对比

## 传统 RAG 系统

RAG（Retrieval-Augmented Generation）的工作方式：
1. 上传一组文件集合
2. LLM 在查询时检索相关片段
3. 生成答案

**代表产品**：NotebookLM、ChatGPT 文件上传、大多数 RAG 系统

### RAG 的局限性

| 问题 | 说明 |
|------|------|
| **无积累** | LLM 在每个问题上都从零重新发现知识 |
| **重复劳动** | 需要综合五个文档的细微问题，必须每次都查找和拼凑相关片段 |
| **临时性** | 没有任何东西被建立起来 |

## LLM Wiki 模式

| 特性 | RAG | LLM Wiki |
|------|-----|----------|
| **知识保留** | 每次查询重新检索 | 持久积累，交叉引用已存在 |
| **维护方式** | 查询时临时生成 | LLM 增量维护，常态化更新 |
| **矛盾处理** | 每次自行发现 | 已被标记并记录 |
| **综合程度** | 临时拼凑 | 反映所有读过材料的综合 |
| **适用场景** | 简单问答 | 需要深度积累的场景 |

## 核心区别

> RAG 是**检索-生成**模式，每次都是临时性的。
> LLM Wiki 是**积累-维护**模式，知识被编译一次并保持最新。

LLM Wiki 的关键差异：**Wiki 是一个持久的、不断复利的工件**。
