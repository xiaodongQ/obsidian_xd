# SSH-MCP 接入评估与落地实施方案

> 文档适用场景：VSCode RemoteSSH 远程编译 + 自定义 AI Skill 自然语言触发，多环境、多集群服务器批量服务备份 / 替换 / 升级 / 重启业务流程。

---

## 核心结论

1. **AI 自然语言驱动自动化集群发布**是 SSH-MCP 的标准核心适用场景
2. SSH-MCP 对远端业务集群机器**零侵入、零安装、零配置修改**
3. 无需推翻现有业务流程，可平滑分层改造
4. 短期自用：`ssh -i/scp -i` 方案足够；中长期规模化：SSH-MCP 是必选
5. RemoteSSH 远程编译链路与 SSH-MCP 改造完全解耦

---

## 适用场景判断

### 你的场景（命中判断）
- ✅ AI 自然语言驱动多环境集群自动化发布
- ✅ 多套独立环境（测试/预发/生产）、多台服务器、多个业务服务批量操作
- ✅ 需要安全防护（防 AI 误操作）、流程稳定性、审计日志

### 非必选场景
- ❌ 纯人工手动发布场景，原生 `ssh -i` 足够

---

## 现有链路 vs MCP 改造后链路

| | 现有链路 | MCP 改造后 |
|---|---|---|
| 底层 | AI Skill → `ssh -i/scp -i` 直连 → 远端服务器 | AI Skill → 本地 SSH-MCP 中控代理 → 原生 SSH → 远端服务器 |
| 凭据 | 私钥硬编码，高泄露风险 | 凭据完全隔离，统一托管 |
| AI 误操作 | 无防护，裸奔执行 | 白名单 + 环境隔离，双层拦截 |
| 会话 | 短连接易断连 | 长连接会话，流程连贯 |
| 审计 | 无结构化日志 | 全链路留痕 |

---

## SSH-MCP 部署边界（关键）

**仅需在本地/中控开发机部署，远端集群零要求：**
- ❌ 无需安装任何代理/守护进程
- ❌ 无需修改系统环境、sshd 配置
- ❌ 无需新增端口、白规则
- ✅ 仅需保留原生 OpenSSH Server（与现有 `ssh -i` 要求一致）

---

## 分阶段落地路径

| 阶段 | 触发条件 | 执行方式 |
|------|---------|---------|
| 短期沿用 | 仅个人自用、环境少、无审计需求 | 继续 `ssh -i/scp -i`，零改造 |
| 平滑过渡（推荐） | 环境逐步增多、担心 AI 误操作 | 本地部署 MCP，新增/核心环境优先接入 |
| 全面接入 | 需团队共用、有合规要求、规模扩大 | 全面替换，统一 MCP 调度 |

---

## 最简平滑改造 5 步

1. **本地部署 SSH-MCP**：中控机完成密钥、环境信息统一配置托管
2. **上层 Skill 逻辑完全不变**：自然语言解析、业务编排逻辑保留
3. **底层执行层兼容替换**：统一调度入口，新增环境走 MCP，存量保留原方案
4. **存量逐步迁移**：后续迭代中切换 `ssh -i` 为 MCP 调用
5. **启用审计与权限管控**：开启日志、命令白名单、环境隔离
